# SIGNUP_FLOW_RELEASE_READINESS v0.1

감사일: 2026-08-27  
감사 범위: `회원가입 중 서비스·가격 최초 등록 → 개인정보/계정 → 최종 가입 → 영업시간/직원 초기 설정`  
용어 정의: 가입 첫 단계에서 서비스명과 가격을 입력하고, 가입 완료 시 매장 계정에 저장합니다.  
감사 방식: 로컬 코드·마이그레이션·개발 데모·테스트 자산 읽기 및 비파괴 검증  
제외: Production 배포, Production DB 적용, 실제 회원 생성

## 2. 현재 완료

- 개발 Preview에서 승인된 세 단계와 마지막 한 번의 비저장 요청을 확인했다.
- Preview의 개인정보 입력 전 가격표 사진과 입력값은 브라우저 메모리에만 남는다.
- 가입 후 초기 설정 가이드는 영업시간·휴무일 → 직원·근무표 두 단계로 축소돼 있다.
- 기존 제품에는 영업시간, 휴무일, 직원, 근무표의 실제 저장 경로가 있다.
- 기존 오너용 요금표 사진 판독기에는 불확실 값 표시와 직접 검토 구조가 있다.

## 3. 현재 안 되는 것

- 실제 `/signup`에는 서비스·상세 요금 등록 단계가 없다.
- 가입 전 가격표 사진을 영구 저장 없이 판독하는 실제 API가 없다.
- 최종 가입 요청에 확인된 서비스 요금이 포함되지 않는다.
- 기본 7개 서비스와 사진 판독 서비스가 중복되지 않도록 대체·조정하는 저장 규칙이 없다.
- 새 흐름의 재개, idempotency, 모바일 접근성 E2E, Production 환경 검증이 끝나지 않았다.

## 4. 출시 전 필수

1. 실제 `/signup`을 승인된 3단계로 교체하고 최종 한 번의 서버 저장 경계를 연결한다.
2. 가입 전 비영구 이미지 판독 API에 파일 검증·요청 제한·실패 시 직접 입력을 구현한다.
3. 확인된 요금 초안을 canonical 서비스/상세 요금에 저장하고 기본 7개 예시 서비스는 대체·조정한다.
4. 최종 가입 요청 idempotency와 단계별 보상 삭제/관측을 보강한다.
5. PC·모바일 전체 E2E 후 Production migration/RLS/key/deploy 상태를 비파괴 점검한다.

## 5. 대표 결정 1개

가격표 원본 사진을 판독 후 즉시 폐기할지, 가입 완료 뒤 매장 자료로 보관할지 결정이 필요하다. 개인정보·보안 부담을 줄이는 기본안은 **판독 후 즉시 폐기하고, 오너가 명시적으로 보관을 선택할 때만 가입 완료 후 비공개 저장**이다.

## 6. 출시 가능 판정

**불가**

개발 Preview는 흐름 검토용으로 작동하지만 실제 회원가입 라우트, 가입 전 비영구 판독, 확인된 서비스 요금의 최종 저장, 중복 서비스 조정이 연결되지 않았다. 따라서 현재 Production에 올리면 대표가 확정한 회원가입 흐름으로 동작하지 않는다.
