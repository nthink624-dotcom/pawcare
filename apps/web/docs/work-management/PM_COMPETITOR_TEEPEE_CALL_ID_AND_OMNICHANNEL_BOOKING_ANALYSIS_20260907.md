# TEEPEE 콜아이디·전화·문자·모바일 예약 분석

- 업무 ID: `PM_COMPETITOR_TEEPEE_CALL_ID_AND_OMNICHANNEL_BOOKING_ANALYSIS_20260907`
- 기준일: 2026-09-07 (KST)
- 범위: 공개된 공식 자료와 `D:\petmanager` 현재 소스의 읽기 전용 대조
- 판정 표기: `CONFIRMED`는 직접 근거가 있는 사실, `UNVERIFIABLE`은 공개 공식 근거로 확인할 수 없는 항목이다.

## 대표용 한 페이지

### 먼저 결론

TEEPEE의 **‘콜아이디’는 별도 상품명이 아니라 티피매니저 예약관리 안에 표시된 기능명**이다. 공식 홈페이지는 이 이름만 소개할 뿐, 전화가 왔을 때 고객 정보가 뜨는지, 부재중 전화를 저장하는지, 문자나 예약 링크가 자동 발송되는지, 별도 번호가 필요한지까지는 공개하지 않는다. 따라서 이를 AI 전화·자동 문자·통화녹음 기능으로 단정하면 안 된다.

펫매니저에는 이미 고객이 휴대폰에서 앱 설치 없이 여는 **매장별 예약 링크**, 고객이 직접 입력하는 예약 흐름, 오너 인앱 접수 알림, 예약 이후 알림톡 흐름이 있다. 부족한 것은 **전화가 왔다는 사건을 펫매니저 고객·예약 흐름과 연결하는 부분**이다.

### 추천 방향

1. **지금:** 기존 예약 링크를 쉽게 복사·공유하고, 전화 상담 중 고객 동의를 받은 뒤 `예약 링크 보내기`를 누르는 흐름을 먼저 검증한다.
2. **MVP:** 국내 기업전화 파트너를 이용해 수신·부재중 전화 사건을 오너 화면에 가져오고, 번호가 기존 고객과 일치하면 “추정 고객”으로만 보여준다. 예약은 절대 자동 생성하지 않는다.
3. **2단계:** 법률·개인정보·발신번호·수신거부 운영이 확인된 뒤에만 부재중 안내 자동화, 문자 수신함, 팀 공유를 검토한다.
4. **나중:** 통화녹음·음성전사·AI 요약은 동의, 고지, 보존·삭제, 접근권한이 훨씬 복잡하므로 별도 사업성이 증명되기 전에는 만들지 않는다.

### 대표가 이해할 실제 사용 장면

```text
고객이 매장에 전화
  → 받았으면: “예약 링크를 문자로 보내드릴까요?” 동의 확인
  → 못 받았으면: 오너 화면에 부재중 전화 표시, 먼저 전화로 용도 확인
  → 오너가 ‘예약 링크 보내기’ 선택
  → 고객 휴대폰에서 링크 열기
  → 서비스·담당자·시간 선택 후 고객이 직접 예약
  → 오너에게 새 예약 알림
```

자동 문자부터 시작하지 않는 이유는, 전화를 한 사실만으로 광고성 정보 수신 동의가 생긴다고 단정할 수 없고 잘못된 고객 매칭·중복 발송도 막아야 하기 때문이다.

### 선택안

| 선택 | 장점 | 큰 문제 | 판정 |
|---|---|---|---|
| 휴대폰 콜아이디를 자체 개발 | 화면을 직접 설계할 수 있음 | Android는 사용자가 단 하나의 call-screening 역할 앱으로 선택해야 하고, iOS는 사전 적재된 번호 식별 중심이라 실시간 CRM 조회에 제약이 큼 | **지금 하지 않음** |
| 통신 API만 구매해 직접 연결 | 제품 제어권이 큼 | 번호·회선·웹훅·장애·발신번호·문자 준법 운영 부담이 모두 펫매니저에 생김 | 공급사 확인 후 조건부 |
| 국내 기업전화 파트너 + 펫매니저 예약 UI | 번호·통화는 통신사가, 고객·예약은 펫매니저가 담당 | 파트너가 안전한 API/웹훅을 제공해야 함 | **추천** |

### 다음 결정 전 확인할 것

- TEEPEE 콜아이디의 정확한 동작은 공개 근거가 없어 `UNVERIFIABLE`이다. 경쟁사 문의는 이번 범위에서 하지 않았다.
- 펫매니저와 연결 가능한 기업전화 공급사의 수신/부재중 웹훅, 기존 번호 유지, 번호 이동, 계약 해지 시 번호 귀속, API 가격은 제안서가 필요하다.
- 자동 부재중 문자의 적법 근거, 정보성/광고성 구분, 수신거부 처리, 개인정보처리방침 문구는 실제 설계가 정해진 뒤 출시 전 최종 검토가 필요하다.

| 질문 | 결과 | 판정 |

## 2. TEEPEE의 전화·문자·모바일 예약 연결

### 공개 근거로 그릴 수 있는 연결

| 영역 | 공개된 사실 | 연결 여부 |
|---|---|---|
| 전화 | 예약관리 기능 목록에 `콜아이디`가 있음 | 전화 사건이 어떤 데이터로 들어오는지는 UNVERIFIABLE |
| 카카오 | 동의서, 예약 변경, 예약금, 방문일 안내 등을 알림톡으로 제공한다고 소개 | TEEPEE 내부 예약·운영 정보와 카카오 메시지 연결은 CONFIRMED |
| SMS 문자 | 공식 웹·스토어 소개에서 SMS 발송 기능을 확인하지 못함 | UNVERIFIABLE |
| 모바일 예약 | 헬로티피에 예약 내역과 매장·예약 메뉴가 존재 | 보호자용 예약 표면은 CONFIRMED, 비회원 공개 링크·예약 단계는 UNVERIFIABLE |
| 보호자 앱 | 공지·알림장·동의서 기능을 제공한다고 소개 | CONFIRMED |
| 예약금 | 카카오로 결제 요청, 기한 내 미결제 시 자동 취소를 소개 | CONFIRMED |

따라서 “전화가 오면 콜아이디가 고객을 찾고, 자동 문자를 보내며, 고객이 휴대폰으로 바로 예약한다”는 하나의 연속 흐름은 **공개 공식 근거로 확인되지 않았다**. 확인되는 제품 조각들을 임의로 이어 붙이지 않는다.

### 개인정보 표시에 관한 참고

- App Store의 개발자 자가신고에는 신원에 연결될 수 있는 이메일·이름·전화번호·사용자 ID와, 신원에 연결되지 않을 수 있는 주소·사진/영상·기기 ID가 표시된다. Apple이 검증한 내용은 아니다.
- 헬로티피 탈퇴 안내는 계정·프로필·반려동물 정보 삭제와 일부 결제·분쟁 기록 보관을 설명한다.
- App Store에 연결된 TEEPEE 개인정보처리방침 본문은 이번 확인 환경에서 열리지 않아, 콜아이디가 처리하는 전화번호·통화기록·수탁자·보유기간은 확인하지 못했다.

| 메시지가 자동으로 간다 | 카카오 운영 메시지 CONFIRMED | 예약 이후 알림톡 다수 구현 | 전화 문의와 예약 알림을 별도 사건으로 유지 | 유지·정리 |
| 통화를 녹음·요약한다 | UNVERIFIABLE | 없음 | 사업성 검증 전 제외 | P3 |

## 5. 도입안

### 0단계 — 제품을 만들기 전에 확인 (1~2주)

초기 테스트 매장 20곳 중 실제 전화 예약 비중이 있는 매장을 대상으로 개인정보 없이 다음 수치만 집계한다.

- 하루 예약 문의 전화 수 범위
- 미용 중 놓치는 전화 수 범위
- 놓친 전화에 다시 연락하는 평균 시간대
- 전화 뒤 고객에게 예약 링크를 보내도 되는지
- 기존 대표번호를 반드시 유지해야 하는지
- Android/iPhone 사용 비중

통화 내용이나 고객 전화번호는 조사 기록에 저장하지 않는다.

**진입 기준:** 5개 이상 매장에서 주 3회 이상 반복되는 문제이고, 절반 이상이 “전화 상담 후 링크 보내기”를 실제로 쓰겠다고 답할 때 공급사 검증으로 간다. 이는 계획 기준이며 시장 사실이 아니다.

### MVP — 상담 후 예약 링크 보내기

#### 화면

- 오너 화면에 `전화 문의` 작업함
- 시각, 수신/부재중 상태, 매장 회선, 처리 상태만 우선 표시
- 기존 고객과 번호가 정확히 일치해도 `OO 보호자일 수 있어요`로 표시
- CTA는 하나: `예약 링크 보내기`
- 전송 전 `고객이 링크 수신에 동의했어요` 확인
- 전송 결과, 실패, 수신거부만 최소 기록

#### 동작

1. 전화 파트너가 서명된 웹훅으로 수신·종료·부재중 사건을 보낸다.
2. 펫매니저는 공급사 event ID로 중복을 막는다.
3. 번호는 정규화 후 같은 매장 안에서만 고객 후보를 찾는다.
4. 직원이 통화 중 링크 수신 의사를 확인한다.
5. 직원이 버튼을 눌러 매장 예약 링크를 보낸다.
6. 고객이 휴대폰에서 직접 예약한다.
7. 기존 예약 생성 흐름부터는 현재 펫매니저 계약을 그대로 사용한다.

#### 금지

- 전화번호만으로 자동 예약 생성
- 이름이 같다는 이유로 고객 확정
- 전화를 했다는 이유만으로 자동 광고 발송
- 개인 직원 번호를 발신번호로 사용
- 동의 없이 통화녹음·전사

### 2단계 — 데이터가 증명한 뒤

- 부재중 전화 자동 안내: 법적 근거와 정보성 문구가 검토된 경우에만 매장별 opt-in
- SMS 양방향 수신함과 팀 담당자 배정
- 고객이 문자 답장 없이 링크에서 직접 예약하도록 단일 CTA 유지
- 전화→링크→예약 전환 분석
- 기존 번호 유지/번호 이동을 지원하는 파트너 계약

### 3단계 — 별도 승인 대상

- 통화녹음
- 음성 전사·요약
- AI가 예약 정보를 추출하거나 답변
- AI 음성 자동 응대

이 기능들은 원본 음성, 민감한 대화 내용, 제3자 정보가 포함될 수 있으므로 별도 개인정보 영향 검토·동의/고지·보존/삭제·모델 제공자 계약·오류 책임 설계가 선행돼야 한다.

## 6. Build / Buy / 제휴 판단

### 자체 모바일 콜아이디 개발을 추천하지 않는 이유

- Android의 `CallScreeningService`는 사용자가 해당 앱을 call-screening 역할 앱으로 선택해야 하며 한 번에 하나의 앱만 그 역할을 맡는다. 전화가 울리기 전에 제시간에 응답해야 한다.
- iOS Call Directory Extension은 전화번호와 라벨 목록을 미리 제공하는 식별 방식이며, 수신 전화마다 웹 서비스에 실시간 조회를 요청할 수 없다고 Apple이 명시한다.
- PC SaaS, Android, iPhone에서 동일한 경험을 만들기 어렵고, 기기 설정·권한 지원 비용이 크다.
- 기존 매장 대표번호, 착신, 회선 장애와 해지 시 번호 귀속까지 제품팀이 직접 책임지게 된다.

### 추천 구조

| 층 | 담당 |
|---|---|
| 전화번호·착신·통화 품질·발신번호 | 국내 통신사/기업전화 파트너 |
| 수신·부재중 사건과 서명된 웹훅 | 통신 파트너 |
| 고객 후보·예약 링크·예약 생성·오너 작업함 | 펫매니저 |
| 알림톡 | 현재 Ssodaa 기반 펫매니저 발송 계약 유지 |
| SMS | 별도 승인된 국내 메시징 제공자, 발신번호 등록·수신거부 포함 |

### 공개 비용 참고

LG U+ `AI비즈콜`은 공개 페이지에서 다음 가격을 안내한다. 이는 **통신 파트너 비용의 참고치일 뿐 펫매니저 선정 공급사나 API 연동 가격이 아니다.**

- 기존 U+ 인터넷전화 결합 부가서비스: 회선당 월 3,300원(3년 약정)~6,600원(무약정), VAT 포함
- 인터넷전화 포함 패키지: 회선당 월 6,600원~11,000원, 3년 약정 기준, VAT 포함
- 기존 인터넷전화가 고급형 센트릭스 또는 DCS여야 하는 조건이 있음

네이버클라우드 SENS는 SMS·알림톡 API, 발송 이력, SMS failover, 080 수신거부 서비스를 제공한다. 공개 가격 페이지는 080 수신거부 번호를 월 29,000원(VAT 별도)으로 표시하지만, 이번 크롤링 결과에서 국내 SMS 건당 단가는 표시되지 않아 숫자를 쓰지 않는다.

#### 실제 비용 계산식

`월 비용 = 회선 기본료 × 매장 회선 수 + 통화료 + SMS 성공 건수 × 건당 단가 + 080/수신거부 비용 + API/CTI 옵션 + 펫매니저 개발·모니터링·고객지원 비용`

통화녹음·저장·AI 전사는 별도 저장량·처리량 비용으로 분리한다. 공급사 견적 전에는 고객 가격이나 무료 제공량을 확정하지 않는다.

| 최소 수집 | MVP에서 음성·통화 내용·기기 통화기록을 수집하지 않음 | 필요 없는 원본 통화 데이터 저장 |

KISA 2026년 제7차 불법스팸 안내서는 ‘혜택 알림’ 같은 모호한 표현으로 광고 동의를 받지 말 것과 광고 수신거부 절차를 복잡하게 만들지 말 것을 안내한다. 정보통신망법 제50조는 광고성 정보의 사전 동의, 수신거부 후 전송 금지, 야간 전송에 대한 별도 동의, 발신자·수신거부 방법 표시를 규정한다. 전기통신사업법 관련 규정은 거짓 발신번호 표시를 금지한다.

수치 목표는 내부 파일럿 목표이며 시장 평균으로 주장하지 않는다.

### 즉시 중단

- 고객이 요청하지 않은 홍보 문구가 자동 발송됨
- 수신거부 고객에게 발송됨
- 다른 고객의 이름·반려동물·예약이 표시됨
- 같은 전화 사건으로 중복 메시지가 발송됨
- 매장 또는 직원 개인번호가 노출됨
- 공급사 서명 검증 실패 사건이 저장·처리됨
- 녹음·통화 내용이 승인 없이 수집됨

## 9. 확인해야 할 공급사 질문

5. 개인 휴대폰에서 회사 번호로 발신·수신할 수 있는가?
6. SMS 발신번호는 어떻게 등록하고, 양방향 문자와 080 수신거부를 지원하는가?
7. 통화·문자 메타데이터의 보관 위치, 기간, 재위탁자, 삭제 API는 무엇인가?
8. 매장당/회선당/API당/통화당/문자당 가격과 최소 약정·설치비·해지비는 얼마인가?
9. 통화녹음을 완전히 끈 계약과 데이터 미보관 옵션이 있는가?
10. API 사용 중단·장애 시 기존 전화 수신은 계속 가능한가?
