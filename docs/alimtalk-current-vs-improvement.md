# 알림톡 현행 문구와 개선안

## 확인 기준

- 이 문서는 PC와 모바일 코드 registry에 있는 **현재 코드상 문구**를 기준으로 작성한다.
- 실제 고객 수신 본문·버튼의 정본은 Ssodaa 승인 템플릿이다. Ssodaa 읽기 전에는 승인본과 코드 초안이 같다고 단정하지 않는다.
- 제외: `booking_manage_link_requested`, `booking_time_proposed`. 고객이 직접 예약을 확인·변경하는 흐름을 유지하며, 링크 재발송 알림톡은 보내지 않는다.

## PC 코드에 현재 문자 그대로 들어 있는 본문

### 예약 확정 (`booking_confirmed`)

```text
[#{매장명}]
#{보호자명}님, #{반려동물명} 예약이 확정되었어요.

방문 일정: #{예약일시}
예약 서비스: #{서비스명}

방문 전 준비사항: #{방문준비사항}

예약 링크
#{예약 링크}
예약 확인 링크
#{예약 확인 링크}
```

### 예약 취소 (`booking_cancelled`)

```text
[#{매장명}]
#{반려동물명} 보호자님, 예약 취소가 처리되었어요.

취소된 예약: #{예약일시}

일정 변경이 필요하시면 아래 링크에서 새 시간을 선택해 주세요.

예약 링크
#{예약 링크}
예약 확인 링크
#{예약 확인 링크}
```

### 예약 변경 확정 (`booking_rescheduled_confirmed`)

```text
[#{매장명}]
#{반려동물명} 보호자님, 예약 변경이 확정되었어요.

새로운 일정: #{예약일시}
예약 서비스: #{서비스명}

방문 전 준비사항: #{방문준비사항}

예약 링크
#{예약 링크}
예약 확인 링크
#{예약 확인 링크}
```

### 방문 직전 (`appointment_reminder_10m`)

```text
[#{매장명}]
#{반려동물명}의 미용 예약 시간이 가까워졌습니다.

예약 일시: #{예약일시}
예약 서비스: #{서비스명}

방문 전 준비사항: #{방문준비사항}
```

### 내일 방문 (`visit_schedule_notice`)

```text
[#{매장명}]
내일은 #{반려동물명}의 미용 예약일입니다.

예약 일시: #{예약일시}
예약 서비스: #{서비스명}

방문 전 준비사항: #{방문준비사항}
```

### 오늘 방문 (`visit_reminder_notice`)

```text
[#{매장명}]
오늘은 #{반려동물명}의 미용 예약일입니다.

예약 일시: #{예약일시}
예약 서비스: #{서비스명}

방문 전 준비사항: #{방문준비사항}
```

### 미용 시작 (`grooming_started`)

```text
[#{매장명}] 미용 시작 안내
#{보호자명}님, #{반려동물명} 미용을 시작했습니다.

#{반려동물명}의 상태를 살피며 차분히 진행하겠습니다.
완료되면 픽업과 케어리포트를 안내드릴게요.
```

### 픽업 준비 (`grooming_almost_done`)

```text
[#{매장명}]
#{반려동물명} 미용을 마무리하고 있어요.

#{픽업안내}
```

### 미용 완료 (`grooming_completed`)

```text
[#{매장명}]
#{반려동물명} 미용이 완료되었습니다.

오늘 사진과 케어리포트를 아래에서 바로 확인하실 수 있어요.
편하신 시간에 픽업 부탁드립니다.

케어리포트 링크
#{예약 확인 링크}
```

### 재방문 (`revisit_notice`)

```text
[#{매장명}]
#{반려동물명}의 다음 케어 시기가 다가왔어요.

마지막 방문: #{마지막방문일}
권장 관리 주기: #{관리주기}

원하시는 날짜와 시간을 편하게 선택해 주세요.
```

| 알림 | 현재 코드상 문구 요지 | 개선 문구 | 이유 / 대표 버튼 |
| --- | --- | --- | --- |
| 예약 확정 | `반려동물명 보호자님, 예약이 확정` + 일시·서비스 + 예약/확인 링크 2개 | `보호자명님, 반려동물명 예약이 확정되었어요.` + 방문 일시·서비스·`방문 전 준비사항` | 보호자/반려동물/일정/서비스를 한 번에 확인. `예약 확인` 하나 |
| 예약 취소 | 취소 일시 + 예약/확인 링크 2개 | `예약 취소가 처리되었어요.` + 취소 일시 + `새 시간을 선택해 주세요.` | 링크 중복 제거. `다시 예약` 하나 |
| 예약 변경 확정 | 새 일정·서비스 + 예약/확인 링크 2개 | `예약 변경이 확정되었어요.` + 새 일정·서비스·`방문 전 준비사항` | 변경 결과를 명확히 안내. `예약 확인` 하나 |
| 내일 방문 | 내일 예약일 + 일시·서비스 | 내일 예약일 + 일시·서비스 + `방문 전 준비사항` | 매장별 준비를 미리 전달. `길찾기` 하나 |
| 오늘 방문 | 오늘 예약일 + 일시·서비스 | 오늘 예약일 + 일시·서비스 + `방문 전 준비사항` | 직전 준비 누락 방지. `길찾기` 하나 |
| 방문 직전 | 예약 시간이 가까움 + 일시·서비스 | 예약 시간이 가까움 + 일시·서비스 + `방문 전 준비사항` | 과한 친근 표현 없이 바로 행동을 안내. `길찾기` 하나 |
| 미용 시작 | 미용 시작 + 안심 문구 | `보호자명님, 반려동물명 미용을 시작했습니다.` + 상태를 살피며 진행 | 진행 상태를 차분하고 정확하게 전달. `예약 확인` 하나 |
| 픽업 준비 | `곧 끝나요`, `잠시 후` 등 유사 문장이 반복될 수 있음 | `반려동물명 미용을 마무리하고 있어요.` + `#{픽업안내}` | 시간 단위를 중복 조합하지 않음. `예약 확인` 하나 |
| 미용 완료 | 완료·픽업 안내 중심 | `사진과 케어리포트를 아래에서 바로 확인하실 수 있어요.` + 픽업 안내 | 결과물을 바로 보게 함. `사진·케어리포트 확인` 하나 |
| 재방문 | `재방문 시기가 가까워졌어요.` | 마지막 방문일 + 권장 관리 주기 + 예약 안내 | 광고가 아니라 관리 근거를 제시. `바로 재예약` 하나 |

## 공통 변수

기본: `매장명`, `보호자명`, `반려동물명`, `예약일시`, `서비스명`.

추가: `방문준비사항`, `픽업안내`, `마지막방문일`, `관리주기`, 예약 확인/재예약 링크.

원장 추가 문구는 승인 템플릿의 `#{추가안내}` 한 변수에만 넣는다. 전체 본문이나 버튼 문구를 임의로 바꾸지 않는다.

## 적용 전 필수 확인

1. 각 변수의 실제 데이터 원천과 빈 값 처리
2. PC·모바일 registry, dispatch, 승인 템플릿 코드·본문·버튼의 일치
3. Ssodaa 승인 템플릿에서 본문·버튼·변수 승인 및 연결
4. provider 실패·timeout은 성공 표시하지 않고, 중복 방지·크레딧 환불 기록을 확인
