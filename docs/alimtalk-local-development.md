# 로컬 알림톡 실행과 운영 보호

로컬 문안 조회에는 웹 서버와 로컬 알림톡 중계서버가 모두 필요하다. 화면을 복구하려고 로컬 조회 주소를 운영 공용 서버로 바꾸지 않는다.

## 시작

- 일반 개발: 저장소 루트에서 `npm run dev` 또는 `npm run dev:webpack`.
- 웹 서버가 이미 실행 중일 때 중계서버만 준비: `npm run relay:local --workspace=@petmanager/web`.
- 시작기는 기존 프로세스를 종료하지 않는다. 포트가 다른 서버 또는 전체 권한 중계서버에 점유됐으면 명시적으로 실패한다.
- 포트 열림뿐 아니라 조회 모드, 로컬 인증키, 실제 공급사 분류 조회까지 성공해야 웹 시작으로 넘어간다.
- `dev:frontend`는 중계서버를 기동하지 않는 화면 전용 명령이다.

## 고정 경계

- 정본 로컬 설정은 `apps/web/.env.local`이다. 예전 `D:\petmanager-shared` 설정이나 루트의 과거 복사본으로 덮어쓰지 않는다.
- 승인된 개발 DB와 두 loopback relay 주소를 시작 전에 확인한다. 운영 DB override 또는 공용 relay 주소는 거부한다.
- 최초 준비 시 로컬 전용 인증키를 생성하고 `ALIMTALK_RELAY_ACCESS_MODE=read-only`를 저장한다. 키는 출력하지 않는다.
- backend 로컬 설정에 `RELAY_ACCESS_MODE=read-only`를 동기화한다. 이 값은 프로세스 기동 때 고정되며 관리 API로 해제할 수 없다.
- health와 템플릿 목록·상세·분류 조회만 허용한다. 등록·검수·중지·실제 발송·발송내역·설정 API는 403으로 거부한다. 공급사 전송 계층에서도 조회 경로 외의 요청을 차단한다.
- 웹 서버도 검수 제출을 DB 상태 변경 전에 거부하고 발송을 전송 계층 진입 전에 거부한다. 중계 주소가 사라져 직접 공급사 전송 경로로 전환되더라도 조회 모드의 발송 차단은 유지된다. 개발 DB의 초안 저장은 허용한다.
- 새 로컬 인증키는 운영 공용 relay 인증키와 공유하지 않는다. 기존 전체 권한 프로세스를 재사용하지 않는다.

## 검증과 범위

`npm run test:local-alimtalk --workspace=@petmanager/web`, `npm run test:alimtalk-relay`, `npm run typecheck:alimtalk-relay`로 시작 조건, 조회 모드 차단, 기존 전체 권한 동작을 검증한다.

실제 화면 검증은 로컬 owner API와 본문·미리보기까지 확인한다. 조회 실패는 승인 여부 미확인이며, 승인 문안이 없다는 근거가 아니다. 실제 고객 발송은 별도의 승인된 테스트 범위가 필요하다.

이 경계는 로컬 인증과 서버/전송 계층의 작업 제한이다. 공급사 계정을 별도로 만들거나 공급사 API키 자체에 읽기 전용 권한을 부여한 것은 아니다. 공급사 키는 서버 환경에만 남고 브라우저로 전달하지 않는다.

운영은 `RELAY_ACCESS_MODE`가 없으면 기존 전체 권한 동작을 유지한다. 이 로컬 작업으로 운영 설정이나 배포를 변경하지 않는다. 기존 운영 환경에 로컬 `.env`를 복사하지 않는다.

## 종료와 재사용

일반 개발 시작기가 직접 만든 중계서버는 웹 시작기 종료 시 함께 종료한다. 이미 실행 중인 안전한 중계서버는 재사용만 하며 종료하지 않는다. `relay:local`로 따로 시작한 서버의 PID/모드/로그 경로는 `apps/web/.tmp/runtime-logs/alimtalk-read-only-runtime.json`에 기록된다.
