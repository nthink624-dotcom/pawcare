## UI·문구 변경

- 기존 예약 상세의 16px 본문/입력, 13px 보조 설명, 44px 이상 컨트롤, 기존 색상·모서리·간격을 재사용했습니다. 고객 제목은 강제 말줄임 대신 줄바꿈합니다.
- 고객은 요청액 → 입금 안내 → 입금자명·신고 순서로 봅니다. 신고 후 매장 확인 대기를 안내하고, 확정과 실제 입금 확인을 구분합니다.
- 고객에게 배분/승계 원장 설명과 내부 처리 이력을 나열하지 않습니다. 차감·환불·수수료·입금 미확인 경고는 유지합니다.
- 취소된 예약에는 미용 요금/남은 결제 금액 행을 표시하지 않습니다. 오너는 환불·수수료 확인, 고객은 추가 송금 금지를 안내받습니다. 정산 값 자체는 변경하지 않습니다.
- 같은 날 안내: “같은 날 예약은 예약금을 한 번만 입금하시면 됩니다.”
- “계좌에서 확인한 입금 총액” → “확인된 입금액”. 해당 요청의 실제 계좌 확인액 `receiptTotal`입니다. 승계 자금을 포함한 총액과 혼동하지 않습니다.
- “이 예약 차감 예정” → “이번 예약에서 차감할 금액”; 완료 후 실제 `usedAmount`는 “이번 예약에서 차감한 금액”.
- “사용 가능한 예약금”은 미사용 잔액에서 환불 예정액도 제외한 금액으로 오너 상세에만 표시합니다. “승계 포함 총 예약금”과 “같은 날 이미 차감한 금액”을 별도로 표시합니다. 기존 계산/DB 값을 바꾸지 않았습니다.
- 입금 확인 입력을 앞으로, 정정·일정 변경·추가 정산·이력은 접기 안으로 이동했습니다. 환불 대기이면 환불 입력을 펼칩니다.
- 기존 서버가 예약금 미확인 때문에 거부하는 예약 승인 버튼은 해당 상태에서 노출하지 않습니다. 권한/승인 규칙을 우회하지 않습니다.
- 오늘 화면의 “처리할 상태 없음” 기본 분기를 개선했고, 예약금 확인이 가능한 경우 실제 확인 입력으로 이동하는 버튼을 연결했습니다. 이 하단 버튼의 최종 브라우저 포커스 검증은 아래 한계와 같습니다.
- 개발 환경 안내: “테스트 화면 · 실제 송금 및 메시지 발송 금지”. 특정 고객 이름을 숨기거나 치환하는 제품 코드는 없습니다.

## 미완료 검사·발견 사항

1. UI 1차에서 확인 API 응답을 기다리지 않고 조회해 배분 검사 실패가 기록됐습니다. 후속 실제 조회에서 A1/A2 확정 및 총2만원·배분2만원/0원을 확인했고, 검사 도구는 응답을 기다리도록 수정했습니다. 제품 금전 로직은 바꾸지 않았습니다.
2. 오늘 화면 하단 이동 버튼의 실제 포커스 검증은 미완료입니다. E를 오늘 화면에서 찾는 시점이 맞지 않았고, A의 기존 정정 UI로0원 대기를 재현하려는 추가 검사도 기대한 예약 상태가 되지 않아 중단했습니다. 원래2만원은 확인 API로 복구하고 실제 조회로 재확인했습니다. 정정 이후 예약 상태의 기대/실제 차이는 별도 기능 확인 사항이며, 이번 UI 작업에서 상태 정책을 임의 수정하지 않았습니다. [검사 기록](../../.codex-work/deposit-ui-20261018/today-footer.json)
3. 별도 기존 `booking-policy-deposit-layout-contract.test.mjs`의 즉시 저장 문자열 검사는 기대하는 `optional`과 현재 기능의 `required`가 달라 실패했습니다. 해당 정책 화면과 테스트는 이번 UI 작업에서 수정하지 않았습니다. 이를 포함한 전체 테스트 통과로 보고하지 않습니다.
4. 쏘다 승인/운영 스케줄러/환불 법적 검토는 기존 운영 준비 항목으로 남겼습니다. 이번에 조회·변경·활성화하지 않았고 실제 발송 검증도 하지 않았습니다.
