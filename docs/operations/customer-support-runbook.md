# PetManager 고객지원 운영 런북

이 문서는 저장소에서 확인되는 지원 기능과 안전 경계만 정리한다. 실제 당직 담당자·대체자·고객 안내 연락처·응답 SLA는 대표가 지정하기 전까지 미정이며, 이 문서만으로 운영 인력이 배정됐거나 고객 응답 시간이 보장된다고 간주하지 않는다.

## 모든 요청에 적용

1. 요청이 들어온 시각, 요청 종류, 영향을 받는 매장 범위, 화면/앱 버전, 사용자가 본 오류 문구와 내부 요청 번호만 기록한다. 가능하면 고객·반려동물의 불필요한 세부 정보는 복사하지 않는다.
2. 비밀번호, 인증 코드, API 키, 카드 전체 번호, 복구 키, 고객 사진 원본을 채팅·이메일·운영 메모로 요청하거나 옮기지 않는다. 화면 캡처는 첨부 전에 개인정보가 보이는지 확인하고, 소유자의 동의가 있는 지원 업로드 경로만 사용한다.
3. 고객 데이터 수정·삭제, 결제 환불, 운영 DB SQL, provider 재전송, 배포를 지원 담당자가 임의로 실행하지 않는다. 관련 절차에 필요한 권한·승인·감사 원장이 없으면 상태를 보존하고 대표에게 올린다.
4. 문의함이나 관리자 오류함이 비어 있다는 사실은 저장·수집·전달이 정상이라는 증거가 아니다. 실패한 조회는 “요청 없음”이 아니라 “조회 미확인”으로 기록한다.

## 문의 접수와 확인 경로

| 경로 | 오너 동작 | 관리자 확인 | 현재 확인된 동작과 한계 |
| --- | --- | --- | --- |
| 함께 고쳐요 피드백 | 앱에서 질문·문제·개선 의견을 제출한다. 스크린샷은 동의 시 선택 첨부한다. | 관리자 피드백 화면 | 제출 API가 서버 RPC로 저장하고 관리자 화면은 보이는 동안 30초마다 갱신한다. 이 30초는 화면 확인 주기이며 보존기간이 아니다. 동의해 첨부한 스크린샷은 일시 미디어 기준 60일 보관 후 정리하는 정책이지만, 운영 스케줄의 실제 실행·삭제 readback은 미확인이다. 문자·푸시 알림은 없다. 계약 검사는 통과했지만 실제 오너 제출부터 운영 DB·화면 표시까지의 E2E는 미검증이다. |
| 일반 고객지원 문의 | 오너 웹/앱에서 1:1 문의를 제출하고 상태를 조회한다. | 관리자 홈의 문의 요약 또는 `/admin/support-requests` | 서버에 저장하며 상태는 접수·확인 중·답변·해결·종료로 관리한다. 홈 요약은 활성 상태에서 30초마다 갱신하고, 전체 문의 화면은 진입 시 불러오며 수동 새로고침을 제공한다. 문의 도착 즉시 알림은 확인되지 않았다. |
| 운영 장애 | 고객 문의와 별도로 관리자 오류함(`/admin/operational-errors`)을 확인한다. | 관리자 오류함 | 화면을 열고 있는 동안 60초마다 갱신한다. 자동 당직 경보나 문자·전화·메신저·push가 아니며, Production 저장·정리는 별도 운영 readback 전까지 미완료다. |

접수 확인 문구는 요청이 실제 저장됐음을 서버 응답으로 확인한 경우에만 사용한다. 처리 예상 시간은 공식 SLA가 지정되기 전까지 약속하지 않는다.

## 유형별 처리

### 가입 또는 로그인

- 가입·인증 오류는 고객이 본 오류 문구, 발생 시각, 웹/앱, 앱 버전만 받아 재현 조건을 기록한다. 비밀번호·인증 코드나 계정 토큰은 받지 않는다.
- 가입 API는 단계별 idempotent 서버 흐름을 사용한다. 사용자가 여러 번 눌렀다고 계정 생성·삭제를 반복하거나 Auth/DB를 수동으로 고치지 않는다.
- 서버 설정/저장소 장애로 보이면 동일 가입을 반복시키지 말고 운영 장애로 분류한다. 계정 생성 여부가 불명확하면 먼저 승인된 읽기 전용 확인 절차가 마련될 때까지 재시도를 안내하지 않는다.

### 직원 추가·접근

- 현재 확인된 `staff_members` 흐름은 오너/매니저가 매장별 직원 프로필·근무 정보를 저장하거나 비활성화하는 기능이다. 별도 직원 초대·인증 계정 프로비저닝 API는 저장소 검색에서 확인되지 않았다.
- 직원 로그인/초대가 필요한 요청은 직원 프로필을 추가하는 것과 계정 접근 권한을 부여하는 것을 구분한다. 초대 기능이 확인되지 않으면 임시 비밀번호를 만들거나 다른 사람의 계정을 공유하지 말고 제품 담당자에게 올린다.
- 잘못된 직원 연결은 다른 매장의 계정으로 바꾸지 않는다. 계정과 매장 권한의 현재 상태를 확인할 정식 운영 절차가 없으면 변경하지 않는다.

### 오너 전화번호 또는 로그인 이메일 변경

- 오너 연락처 전화번호는 오너 프로필 설정에서 수정할 수 있다. 로그인 이메일 변경은 별도 경로이며 현재 비밀번호를 요구한다.
- 오너가 로그인 이메일에 접근하지 못하거나 현재 비밀번호를 확인할 수 없으면 지원자가 대신 이메일·인증 정보를 바꾸지 않는다. 현재 관리자 신원 확인 절차와 승인된 계정 복구 담당자가 문서화되지 않았으므로 대표에게 에스컬레이션한다.
- 보호자 연락처 변경은 오너 계정 연락처 변경과 다른 고객 데이터 작업이다. 매장 오너가 앱의 고객 관리 기능을 통해 정정하도록 안내하고 지원자가 임의로 고객 행을 수정하지 않는다.

### 결제·환불

- 결제 내역은 payment ID, provider 주문 번호, 금액·통화, 현재 상태, 관련 문의 번호로 대조한다. 민감한 카드 정보나 결제 비밀키는 수집하지 않는다.
- 현재 관리자 환불 API는 고위험 작업으로 잠겨 있으며, 최근 재인증·2인 승인·내구성 실행 원장이 준비될 때까지 모든 환불을 거부하도록 구현돼 있다. 지원자는 환불 완료를 약속하거나 endpoint를 우회하지 않는다.
- 환불 요청은 대표 승인과 별도 provider readback·실행 절차가 준비될 때까지 접수 상태로 보존한다. provider 대시보드에서 실제 환불을 실행할 권한·절차는 이 런북에서 승인하지 않는다.

### 탈퇴·정보 열람·삭제 요청

- 오너 계정 탈퇴는 공개 탈퇴 화면에서 현재 비밀번호, 명시적 확인, 요청 idempotency를 거치는 셀프서비스 절차로 안내한다. 결제/환불 상태 미확정 또는 보존 대상 확인 시 서버가 거부할 수 있다. 지원자가 DB나 Auth에서 계정을 직접 지우지 않는다.
- 현재 오너 데이터 내보내기는 인증된 오너의 선택 매장 단위 JSON이며, 모든 계정 데이터나 미디어 바이너리를 포함하는 완전한 개인정보 사본으로 안내하지 않는다. 실제 export 생성 또는 탈퇴 처리 전에 오너 동의와 요청 범위를 확인한다.
- 보호자 등 정보주체의 열람·정정·처리정지 요청 담당자, 신원 확인 절차와 SLA는 미확정이다. 확정 전에는 처리 완료 시한을 약속하거나 고객 행을 임의 수정/삭제하지 말고 대표에게 전달한다.

### 데이터 복구 요청

- 데이터 손실 의심은 최소 SEV-1/SEV-2로 분류해 요청 시각·매장 범위·마지막 정상 시각을 보존하고 추가 쓰기·재배포·수동 복구를 멈춘다.
- 현재 백업 증거는 2026-10-03 16:10 UTC 기준 Drive에 2026-10-01 파일 하나가 있으며 메타데이터 나이는 60.63시간이다. 24시간 RPO를 만족하지 않으며 Drive 메타데이터만으로 내부 snapshot 시각도 증명되지 않는다. 복구 드릴은 실제 RPO/RTO·2번째 기기 복구·별도 Supabase/R2 복구까지 검증되지 않았다.
- 따라서 “최근 24시간 이내까지 복구 가능”, “손실 없이 복원 가능”, “복구 완료 시각”을 약속하지 않는다. 복구가 필요하면 장애 런북의 승인·격리 복구 단계를 따른다.

## 에스컬레이션과 종료

- 다른 매장 데이터 노출, 운영 데이터 손실/변조, 결제 중복 또는 자격증명 침해 의심은 SEV-1로 즉시 대표에게 전달한다. 지원자는 흔적을 지우거나 테스트 재현을 위해 운영 데이터를 바꾸지 않는다.
- 다수 매장 예약·저장·결제·알림 실패는 SEV-2, 단일 매장 제한 장애는 데이터 영향이 없다는 증거를 확보한 경우에만 SEV-3로 분류한다.
- 요청 종료 전 관리자 상태와 오너에게 전달한 사실을 확인하고, 저장된 문의 ID·처리 담당 역할·조치 시각·남은 위험만 기록한다. 불필요한 개인정보가 포함된 내부 복사본은 만들지 않는다.

## 아직 운영 전 결정이 필요한 항목

- 실제 지원 담당자와 부재 시 대체자, 연락 경로, 근무 시간과 응답/해결 SLA.
- 직원 로그인 초대·접근 복구의 검증된 제품 흐름.
- 최근 재인증·2인 승인·감사 가능한 환불 실행 절차와 provider readback.
- 정보주체 권리 요청의 신원 확인·담당자·기한·보존 예외 절차.
- 반복 암호화 백업·60일 Drive 보존 동작·최신 24시간 이내 recovery point와 분기별 격리 복구 드릴.

이 항목들이 정해지기 전까지는 내부 응대 참고 문서이며, 고객지원 조직 또는 SLA가 운영 준비 완료됐다는 근거로 사용하지 않는다.
