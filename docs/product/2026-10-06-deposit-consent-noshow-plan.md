# 예약금·동의서·노쇼 및 취소 관리 기획안

작성일: 2026-10-06. 상태: 기획 초안. 제품 코드·DB·알림톡 템플릿·운영 설정 변경 없음.

## 목표와 공통 결정

- 오너가 매장 기본 정책을 정하고 예약별 선택 및 고객별 예외를 적용한다.
- 예약 생성 출처가 웹·모바일·전화·오너 직접 등록 중 무엇이든 같은 정책과 정본 예약을 사용한다.
- 예약, 예약금, 동의서, 발송 결과를 각각 관리한다. 발송 성공은 결제 완료나 서명 완료가 아니다.
- 기본 모드는 기존 예약 확정 흐름 유지다. 예약금 필수 매장은 조건 충족 전 `예약금 대기`로 표시한다. 이때 확정 알림을 보내지 않는다.
- 조건 대기 예약도 정해진 기한 동안 해당 담당자의 시간을 점유하며 중복 예약을 막는다.
- 동의서는 기본적으로 미용 시작 전 완료 조건이다. 미서명만으로 예약을 자동 취소하지 않는다.
- 정책 변경은 새 예약에 적용한다. 기존 예약에는 당시 정책·금액·문구 버전을 보존한다.
- 고객별 예외보다 매장 기본 설정을 낮게, 예약별 오너의 명시적 예외를 높게 적용한다. 알림 수신 거부는 모든 발송 선택보다 우선한다.
- 예약금 면제와 예약금 알림 수신 거부는 다르다. 수신 거부만으로 납부 의무를 면제하지 않는다.

## 현재 코드에서 확인한 출발점

- `owner-mutations.ts`: 오너 직접 등록한 확정 예약에 확정 알림 발송 경로가 있다.
- `customer-bookings.ts`: 고객 예약 후 오너 인앱 알림을 생성한다. 고객 예약 접수 알림톡은 레지스트리 설명과 생성 경로에 차이가 있다.
- `complete-booking/route.ts`: 할인 적용 최종 서비스 금액과 결제 금액을 검증한다. 예약금 전용 흐름으로 그대로 사용할 수 없다.
- `alimtalk.ts`: 현재 취소 문구는 매장 측 사정에 따른 취소다. 고객 취소·미납 취소·노쇼 안내에는 별도 계약이 필요하다.
- 고객 직접 변경·취소 마감이 예약 시작 2시간 전으로 고정되어 있다. 정책 설정과 UI·서버 검사를 함께 연결해야 한다.
- 노쇼 상태와 고객별 횟수 표시는 있다. 고객별 다음 예약 조건과 정책 적용 이력을 추가해야 한다.
- 프로젝트 알림 계약에서 자동 방문 안내는 예약당 가장 적절한 시점에 최대 1회다. 이 규칙을 유지한다.

## 화면 구성

- 매장 정보 > 예약 페이지 > 예약 정책: 예약금, 취소·노쇼, 동의서 기본 선택을 설정한다.
- 동의서 관리: 문서 종류, 버전, 적용 대상, 서명 현황, 발송 이력을 관리한다. 초기에는 매장 설정의 탭으로 제공한다.
- 예약 등록·상세: 예약금/동의서 상태 카드와 `보호자에게 보낼 안내` 영역을 둔다.
- 고객 상세: 해당 매장 노쇼 이력, 다음 예약 조건, 예약금 면제 및 발송 예외를 표시한다.
- 보호자 예약 관리: 예약 확인, 필요한 동의서, 예약금 결제, 변경·취소를 한 링크에서 처리한다.
- PC 본문 16px, 일반 버튼·입력창 높이 40px를 기준으로 한다. 모바일에서도 필요한 내용을 잘리지 않게 표시한다.

## 작업 1. 예약금

### 오너 설정

- 사용 여부: 사용 안 함 / 예약별 선택 / 대상 고객에게 필수.
- 대상: 전체 / 신규 / 노쇼 이력 고객. 고객별 면제 및 예약별 예외 허용.
- 금액: 첫 출시는 정액. 서비스 예상가 비율 방식은 가격 변동·견적 확정 문제를 정리한 후 확장한다.
- 납부 기한: 예약 생성 후 정해진 시간 또는 방문 전 정해진 시각. 방문 시작을 넘는 기한은 허용하지 않는다.
- 미납 조치: 예약 유지하고 오너 확인 / 예약금 대기 후 기한 초과 시 자동 취소.
- 방문 임박 예약: 현실적인 납부 시간이 없으면 오너 확인으로 전환한다. 이미 지난 기한을 부여하지 않는다.
- 예약금 필수 및 노쇼 고객 예외는 수동 등록에서도 확인하고, 면제 사유를 기록한다.

### 예약·결제 흐름

1. 예약 저장과 함께 금액·기한·정책을 확정한다.
2. 예약금 선택형은 기존 확정 상태를 유지한다. 필수형은 예약금 대기로 시간을 확보한다.
3. 오너가 선택한 안내를 보내거나 링크를 복사한다. 발송 거부·잔액 부족·오류도 화면에 표시한다.
4. 보호자가 예약 정책과 금액을 확인하고 결제한다.
5. 서버가 결제 주체·매장·예약·요청 버전·금액을 검증하고, 필수형 예약을 확정한다.
6. 방문 후 최종 서비스 금액에서 유효한 기납부 예약금을 한 번만 차감한다.

예시: 최종 서비스 금액 60,000원, 기납부 예약금 20,000원 → 잔금 40,000원.
서비스 가격이 예약금보다 낮아지면 차액 환불 대상으로 표시한다.

### 상태와 예외

- 예약금 상태: 미요청 / 납부 대기 / 납부 완료 / 기한 초과 / 면제 / 환불 처리 중 / 부분 환불 / 환불 완료 / 환불 실패.
- 계좌 입금은 오너가 확인한 경우에만 `수동 입금 확인`으로 기록한다. 온라인 검증 완료와 구분한다.
- 금액 변경은 기존 미납 요청을 종료하고 새 요청을 발행한다. 납부 완료 금액을 덮어쓰지 않는다.
- 예약 취소 후 늦은 결제, 기한 종료와 결제 동시 발생, 결제 완료 후 예약 저장 실패는 별도 조정 대상으로 기록한다.
- 취소된 시간에 다른 예약이 생겼다면 늦은 결제로 예약을 자동 복원하지 않는다.
- 재시도와 웹훅 중복에도 한 번만 납부·환불·예약 확정 처리한다.

### 완료 기준

- 요청부터 결제 확인·잔금 차감·전체/부분 환불까지 실제 상태가 일치한다.
- 취소/만료된 결제 링크는 새 결제를 시작할 수 없고, 진행 중 결제의 늦은 결과를 처리한다.
- 환불 요청과 환불 완료를 구분하고 오너가 실패 건을 확인할 수 있다.

## 작업 2. 동의서 관리

### 문서 종류와 적용

- 일반 미용, 노령견·기저질환 확인, 입질 등 안전 관련, 추가 서비스 확인을 구분한다.
- 사진 활용·마케팅 동의는 선택 문서로 분리하고 서비스 필수 동의와 묶지 않는다.
- 발송 기본값: 사용 안 함 / 신규 고객 / 해당 조건의 반려동물 / 매 예약.
- 문서마다 유효 범위 지정: 동일 버전 지속 사용 / 반려동물별 / 예약마다.
- 일회성 서명 재사용은 동일 매장·문서 버전·서명자·대상 반려동물·유효 범위가 모두 맞을 때만 허용한다.
- 예약마다 필요한 상태 확인 문서는 과거 서명이 있어도 해당 예약에서 다시 작성한다.

### 작성과 서명 흐름

1. 오너가 템플릿을 선택·편집하고 보호자 화면 미리보기를 확인한다.
2. 수정본은 새 버전으로 발행한다. 이미 서명된 원본은 변경하지 않는다.
3. 예약 조건에 맞는 문서를 선택하고 오너가 보내거나 건너뛴다.
4. 보호자는 본문·필수 확인 사항을 읽고 본인 확인 및 서명을 진행한다.
5. 서명 당시 본문·버전·대상·확인 시각·서명 결과를 묶어 보관한다.
6. 오너는 예약에서 서명본을 열람하고 내려받는다. 보호자도 자신의 작성본을 확인할 수 있다.

### 상태와 운영

- 문서 상태: 미요청 / 작성 대기 / 작성 완료 / 기한 종료 / 철회 요청 / 대체됨 / 해당 없음.
- 발송/전달 상태는 별도다. 링크 열람을 서명 완료로 표시하지 않는다.
- 필수 문서 미완료 시 미용 시작 전에 경고한다. 오너 예외 처리에는 사유를 남긴다.
- 매장·보호자 접근 권한, 본인 확인 수준, 보관 기간, 삭제/철회 절차와 다운로드 권한을 구현 전에 정한다.
- 임의 포괄 면책이나 법적 효력 보장 문구를 제공하지 않는다. 템플릿 문안은 검토 후 발행한다.

### 완료 기준

- 과거 서명본이 템플릿 수정으로 바뀌지 않는다.
- 보호자·반려동물·예약이 다른 서명본을 재사용하지 않는다.
- PC와 모바일에서 같은 서명 현황과 문서 원본을 조회한다.

## 작업 3. 노쇼·예약 취소 관리

### 취소 정책

- 고객 직접 취소 마감, 변경 가능 시점, 마감 후 취소 요청 방식을 매장이 설정한다.
- 마감 후 고객이 취소 의사를 남길 수 있게 한다. 오너가 승인하기 전까지 시간 점유를 유지하고 처리 대기 상태를 표시한다.
- 정상 취소 / 늦은 취소 / 매장 사정 취소 / 미납 취소 / 노쇼를 구분한다.
- 정상 취소와 미납 취소를 노쇼 횟수에 포함하지 않는다. 늦은 취소도 별도 이력으로 관리한다.
- 예약 취소 시 미발송 안내 작업과 미납 결제 요청을 종료하고 일정의 시간을 해제한다.
- 환불 미완료가 예약 취소를 막지 않게 하고, 환불 후속 작업을 별도로 남긴다.

### 예약금 처리

- 매장 사정 취소는 기납부 예약금 전액 환불을 제품 기본안으로 제안한다.
- 고객 취소는 예약 시 확인한 정책에 따라 환불 예상액·차감액·이유를 먼저 표시한다.
- 노쇼 처리 시 예약 상태 변경과 금액 차감 확정은 별도 동작으로 둔다.
- 시간 구간별 차감 설정은 가능하되 실제 금액·문구는 적용 가능 범위를 검토한 후 사용한다. 고정 몰수 비율을 제품의 기본값으로 단정하지 않는다.
- 오너는 전액 환불, 추가 환불, 예외 면제 사유를 기록할 수 있다.
- 예약금을 받지 않은 예약은 추가 요금 자동 청구 없이 다음 예약 조건으로 대응한다.

### 노쇼와 다음 예약 조건

- 시간이 지났다고 자동 노쇼 확정하지 않는다. 방문 여부 확인 필요 표시 후 오너가 판단한다.
- 처리 창: 사유, 연락 여부, 내부 메모, 다음 예약 조건, 고객 안내 선택.
- 오너 선택: 기록만 / 승인 후 확정 / 예약금 필수 / 온라인 예약 제한.
- 제안 기본값: 첫 노쇼 이후 승인 필요. 반복 시 예약금 필수 또는 온라인 제한은 매장이 선택한다.
- 정책은 해당 매장의 보호자 기준으로 적용하고 다른 매장에 공유하지 않는다.
- 고객이 다른 반려동물로 예약해도 같은 보호자 조건을 적용하며, 잘못 연결된 고객을 정정할 수 있다.
- 노쇼 오처리 정정, 다음 예약 1회 예외, 조건 해제와 사유 기록을 지원한다.
- 직접 예약은 제출 전에 조건을 안내한다. 전화·오너 등록도 같은 조건을 검사한다.
- 기존에 확정된 다른 예약의 조건을 조용히 바꾸지 않고 오너 확인 대상으로 보여준다.

### 완료 기준

- 취소 원인별 문구·환불·시간 해제·횟수 집계가 일치한다.
- 노쇼 정정 시 횟수와 자동 정책이 다시 계산되며 수동 예외는 구분해 보존한다.
- 제한된 고객은 서버에서도 제한되고 오너의 명시적 예외만 허용된다.

## 알림톡 통합 설계

### 예약 등록 UI

`보호자에게 보낼 안내`

- 예약 확정 안내: 기존 설정에 따른 자동 발송 상태 표시. 임의 선택 체크박스로 바꾸지 않는다.
- 동의서 요청: 매장 기본 선택, 이미 유효한 서명이 있으면 완료 표시.
- 예약금 요청: 적용 금액·기한·면제 여부와 발송 선택 표시.
- 수신 거부/템플릿 미승인/크레딧 부족 시 이유와 링크 복사 기능 표시.
- 고객 직접 예약은 매장 기본 정책으로 필요한 항목을 만든다. 임의로 필수 조건을 건너뛰게 하지 않는다.

### 메시지 운영

| 사건 | 제안 발송 방식 | 연결 화면 |
|---|---|---|
| 확정 예약 생성 | 출처와 관계없이 확정 알림 자동화로 통일하는 제품안 | 예약 확인 |
| 예약금 필수 조건 대기 | 확정 문구 없는 접수·예약금 요청 | 예약금 결제 |
| 동의서·예약금 선택 요청 | 오너가 선택 후 발송 | 예약 준비 |
| 동의서와 예약금 동시 요청 | 승인된 통합 요청 템플릿 사용 시 1건 | 예약 준비 |
| 방문 안내 | 기존 자동 안내 최대 1회 유지 | 예약 확인 |
| 미서명·미납 재안내 | 첫 출시 오너 수동 선택 | 필요한 작업 |
| 예약 취소 | 취소 주체·사유에 맞는 상태 안내 | 취소 및 환불 내역 |
| 노쇼 기록·조건 변경 | 오너가 선택하여 안내 | 다음 예약 조건 |
| 환불 완료 | 실제 완료 확인 후 안내 | 환불 내역 |

- 확정 안내의 기존 `예약 확인` 링크에서 동의서·예약금도 처리할 수 있게 한다. 현재 승인 본문을 임의로 바꾸지 않는다.
- 필수형 예약은 결제 전 접수 안내, 결제 확인 후 확정 안내를 사용한다. 메시지에 표시하는 상태가 실제 예약 상태와 일치해야 한다.
- 새로운 요청·취소 원인·환불 메시지는 Ssodaa 승인 템플릿 연결 이후에만 발송한다.
- 발송 목적, 요청 버전, 예약 상태 변경 사건별 중복 방지 키를 둔다. 통합 요청 발송 시 개별 요청도 발송 완료 대상으로 연결한다.
- 결과 불명 timeout은 확인 필요로 표시하고, 중복 여부를 확인하기 전 자동 재발송하지 않는다.
- 승인 템플릿·매장 크레딧·고객 수신 설정을 모두 검사한다. 문자로 자동 우회하지 않는다.
- 실패·차단된 요청은 결제·서명 완료로 처리하지 않는다. 보호자 페이지에서 필요한 항목은 그대로 보여준다.
- 자동 취소는 안내 전달 실패 시 실행을 보류하고 오너 확인으로 전환하는 것을 기본안으로 한다.
- 예약 상태·조건·요청 기한 변경은 미발송 작업을 갱신하고, 이전 링크의 쓰기 작업을 막는다.

## 개발 순서와 출시 조건

1. 공통 정책/상태/권한/예약별 정책 보존 및 고객 예약 알림 정책을 확정한다.
2. 동의서 버전·서명·예약별 발송 선택을 구현한다.
3. 예약금 요청·결제 검증·잔금·환불·기한 관리를 구현한다.
4. 취소 원인별 처리와 노쇼 이후 조건을 연결한다.
5. 승인 템플릿 연결 및 전체 예약 흐름을 확인한 뒤 사용 가능한 기능만 노출한다.

결제·서명·개인정보 변경은 기존 작업과 소유권을 확인하고 별도 검증 계획을 수립한다.
기획 승인은 코드 구현, 운영 DB 변경, 실제 발송, 결제, 배포 승인을 대신하지 않는다.

## 구현 전 확정할 정책

- 조건 대기와 결제 후 확정 모드를 첫 출시부터 제공할지 여부.
- 동의서 본인 확인 수단, 보관 기간, 문구 검토 및 필수/선택 구분.
- 예약금 정액 기본 금액, 기한, 매장 환불 정책 적용 범위.
- 늦은 취소의 다음 예약 조건과 노쇼 횟수 기준.
- 메시지 비용 안내, 새 템플릿 승인 상태, 실제 PG 연동 범위.
