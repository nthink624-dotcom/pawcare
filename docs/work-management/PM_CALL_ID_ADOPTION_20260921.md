# 펫매니저 콜아이디 도입 1차 기반

- 기준일: 2026-09-21 (KST)
- 상태: 로컬 소스·계약·집중 테스트 완료, DB 적용·공급사 연결·운영 배포 전

## 이번에 추가한 범위

- `call_integrations`: 매장 유선전화 또는 휴대폰 회선을 전화 공급사와 연결하는 설정. 두 회선을 별도로 등록할 수 있으며, 웹훅 토큰은 키 해시만 저장하고 생성 응답에서 한 번만 반환한다.
- `call_events`: 수신·부재중·응답·종료 이벤트 원장. 원본 전화번호 대신 서버 HMAC 지문과 끝 4자리만 저장한다.
- `POST /api/webhooks/calls/{integrationId}`: 공급사 이벤트를 인증하고, 같은 매장 고객 번호만 대조한 뒤 중복 이벤트를 멱등 처리한다.
- `GET /api/owner/call-events`: 대표/매니저가 최근 이벤트와 매칭된 고객 이름을 확인하는 읽기 경계.
- `POST/GET /api/owner/call-integrations`: 공급사 연동을 만들고 현재 연결 상태를 확인하는 설정 경계.

## 공급사 경계

현재 저장소에는 매장 전화 서비스나 번호가 기록돼 있지 않다. KT 통화매니저 API는 수신 CID, 발신번호, 착신전환, 부재중 안내, SMS 연동을 공식적으로 안내하고 있어 1차 후보로 조사했다.

- 공식 안내: <https://dev.fone.kt.com/useInfo/serviceInfo.dev>
- 실제 연동에는 KT 개발자/셀러 등록, 회선 식별자, API 규격과 웹훅 형식 확인이 필요하다.
- KT가 아닌 전화 서비스를 쓰고 있다면 같은 내부 계약으로 별도 어댑터를 만든다.

## 적용 전 필요한 운영 작업

1. 실제 매장 대표번호의 통신사와 회선 서비스를 확정한다.
2. 개발용 Supabase에 `20260921120000_call_id_foundation.sql`을 별도 승인으로 적용한다.
3. 개발/운영 서버에 `CALL_ID_WEBHOOK_HASH_SECRET`, `CALL_ID_PHONE_HMAC_SECRET`을 각각 생성해 등록한다.
4. 대표/매니저 화면에 연동 설정과 전화 작업함 UI를 연결한다.
5. 테스트 회선으로 수신·부재중·번호 매칭·중복 재전송을 확인한 뒤 운영 적용을 승인한다.

통화 녹음·전사·원본 통화기록은 이번 범위에 포함하지 않는다. 개인정보처리방침에는 전화 이벤트 처리 목적, 보유기간, 수탁자와 삭제 절차를 실제 공급사 계약이 확정된 뒤 반영한다.
