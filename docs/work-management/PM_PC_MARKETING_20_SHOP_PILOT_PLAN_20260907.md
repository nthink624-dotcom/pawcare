# 펫매니저 초기 테스트 멤버 20개 매장 운영안

기준일: 2026-09-07 (KST)  
목표: 연락 20곳이 아니라 `가입 → PASS → 3단계 초기설정 → 테스트 예약 1건`을 마친 **확정 테스트 매장 20곳**을 모집하고, 제품 개선에 계속 참여할 수 있게 운영한다.

## 대표가 먼저 볼 내용

1. 현재 승인된 외부 접촉은 10곳까지다. 20개 확정 매장을 만들려면 실제 전환 결과를 본 뒤 추가 접촉 승인이 필요하다.
2. 첫 유료 결제 후 30일 추가는 대표 결정으로 파일럿 혜택에 포함한다. 다만 실제 지급 구현과 독립 검수가 끝나기 전에는 DM을 보내거나 외부에 약속하지 않는다.
3. 테스트 멤버에게만 오너 화면에 차분한 배너와 피드백 버튼 하나를 보여준다. 고객 예약 화면에는 아무것도 표시하지 않는다.
4. 테스트 멤버 여부는 매장명이나 링크로 추측하지 않고, 운영자가 승인한 매장 ID와 오너 사용자 ID로만 관리한다.
5. 1등 혜택은 **서비스 90일 추가**를 추천한다. 1명 기준 표시가치 87,000원이며 대표가 최종 승인하기 전에는 알리지 않는다.
6. 작거나 중복되거나 QA에서 재현되지 않은 의견도, 내용 있는 실제 의견이면 제출 매장별 한 건에 최소 3일을 지급한다. 1등 점수 경쟁과 기본 3일은 별개다.

## 20곳을 만들려면 몇 곳에 연락해야 할까

아래 숫자는 계획을 세우기 위한 가정이며 실제 성과가 아니다. `가입률`은 DM을 보낸 매장 중 가입한 비율, `가입 후 완료율`은 가입한 매장 중 PASS·3단계·테스트 예약을 모두 마친 비율이다.

| 시나리오 | 가정 | 접촉→확정 테스트 매장 | 20곳에 필요한 접촉 수 | 운영 계획값 |
|---|---|---:|---:|---:|
| 보수 | 가입 20% × 가입 후 완료 50% | 10% | 200곳 | 200곳 |
| 기준 | 가입 35% × 가입 후 완료 60% | 21% | 96곳 | 100곳 |
| 낙관 | 가입 50% × 가입 후 완료 70% | 35% | 58곳 | 60곳 |

계산식은 `필요 접촉 수 = 올림(20 ÷ 접촉→확정 테스트 전환율)`이다. 첫 10곳의 실제 결과가 생기면 이 가정을 버리고 실제 전환율로 다시 계산한다. 현재 승인 범위는 10곳이므로 11번째부터는 대표의 별도 확대 승인이 필요하다.

## 모집 순서

| 단계 | 규모 | 진행 방법 | 다음 단계 조건 |
|---|---:|---|---|
| 준비 잠금 | 0곳 | 공식 발신 계정, CTA, 혜택 지급, 가입 전체 흐름, 기록 방법을 검수 | 모든 항목 PASS |
| 1차 | 기존 후보 1~5, 최대 5곳 | 다음 적격 영업일 19:10~19:50, 10분 간격으로 한 번씩 발송 | 3개 완전 영업일 관찰 |
| 2차 | 기존 후보 6~10, 최대 5곳 | 치명 문제 0일 때만 같은 시간표로 한 번씩 발송 | 두 차수의 D+7 결과 집계 |
| 확대 판단 | 추가 접촉 0곳 | 실제 가입률과 완료율로 20곳까지 남은 필요 접촉 수 계산 | 대표가 추가 접촉 수 승인 |
| 3차 이후 | 승인된 범위에서 회차당 최대 10곳 | 각 회차 사이 3개 완전 영업일 관찰 | 확정 테스트 매장 20곳 도달 시 즉시 종료 |

일정이 지나면 날짜를 고정해서 따라가지 않는다. 모든 준비가 PASS된 **다음 적격 영업일 19:10**을 1차 시작으로 다시 잡는다. 주말 발송, 무응답 재촉, 거절 재접촉, 다른 채널로 우회 연락은 하지 않는다.

### 중단 규칙

- 공식 발신 계정이나 후보 공식성이 확인되지 않는다.
- 확정 DM의 혜택과 실제 지급 계약이 한 문장이라도 다르다.
- 가입·PASS·초기설정·테스트 예약 중 진행을 막는 문제가 생긴다.
- 혜택이 누락·중복·오지급되거나 고객정보·인증정보가 노출된다.
- 같은 매장에 이미 연락했거나 1회 원칙을 지키지 못한다.
- 확정 테스트 매장 20곳에 도달한다.

치명 문제가 한 건이라도 생기면 다음 회차 전체를 멈추고, 문제를 해결한 뒤 독립 검수를 다시 통과해야 한다.

## 테스트 멤버 전용 오너 화면

### 보여줄 것

- 오너 홈 상단에 작은 `초기 테스트 멤버` 배지와 차분한 안내 배너
- 안내 문구: `작은 의견도, 다른 매장의 의견과 겹쳐도 내용이 있는 의견 한 건마다 최소 3일을 더해드려요. 첫 결제 전 무료 이용은 처음 30일을 포함해 최대 60일까지이며, 60일이 된 뒤에도 의견은 계속 남길 수 있어요.`
- `초기 이용 30일`, `피드백으로 추가된 일수`, `첫 결제 후 추가 30일`을 각각 분리한 혜택 내역과 적용 상태
- 영업시간 → 직원·근무시간 → 서비스·가격 → 테스트 예약의 진행률
- CTA 하나: `불편한 점 알려주기`
- 보낸 피드백 목록과 `접수됨`, `기본 혜택 지급`, `제품 검토 중`, `반영 예정`, `반영 완료`, `기존 의견과 겹침` 상태
- 각 의견의 최소 3일 지급 여부, 60일 상한 도달 여부와 지급 완료일
- 제품에 반영된 경우 무엇이 달라졌는지 한두 문장 안내

### 보여주지 않을 것

- 고객 예약 페이지, 고객 알림, 고객 영수증에 테스트 멤버 표시
- 반복 팝업, 강제 설문, 닫히지 않는 배너, 빨간 경고처럼 보이는 디자인
- 경쟁 순위·다른 매장 이름·다른 매장의 점수
- 아직 확정되지 않은 1등 보상이나 지급되지 않은 혜택을 완료된 것처럼 표시

PC와 모바일 오너 화면은 같은 멤버십·혜택·피드백 상태를 읽는다. 일반 사용자는 기존 화면과 기능이 그대로 유지되고 테스트 멤버 UI를 보지 않는다.

## 누가 테스트 멤버인지 정하는 기준

멤버십의 정본은 서버의 안정적인 `shop_id + owner_user_id` 조합이다. 운영 관리자가 승인한 기록만 테스트 멤버가 된다.

다음 정보로 멤버십을 추측하거나 자동 부여하지 않는다.

- Instagram UTM 또는 후보 번호
- 매장명, 오너 이름, 가입일
- PC나 모바일에 남아 있는 로컬 상태
- 특정 링크를 열었다는 사실

필요한 상태는 다음과 같다.

| 상태 | 뜻 | 화면·혜택 처리 |
|---|---|---|
| 가입 예정 | 참여 승인됐지만 계정 연결 전 | 테스트 멤버 UI 없음, 혜택 미지급 |
| 진행 중 | 매장·오너 ID 연결 완료 | 전용 UI와 피드백 동선 표시 |
| 잠시 중지 | 본인 요청 또는 확인 필요 | 새 혜택 지급 중지, 기록 보존 |
| 완료 | 운영 기간을 정상 마침 | 결과와 지급 내역은 읽기 전용 유지 |
| 제외 | 중복 계정, 정책 위반, 잘못 연결됨 | 일반 사용자 상태로 복귀, 사유 코드만 보존 |

상태 변경은 운영 관리자만 하고, 변경자·변경 시각·사유 코드만 남긴다. 이름이나 UTM이 바뀌어도 멤버십은 바뀌지 않는다. 일반 사용자의 가입·요금·UI·혜택 계산에는 영향을 주지 않는다.

## 피드백이 혜택으로 이어지는 순서

| 순서 | 담당 | 처리 시간 | 최소 기록 |
|---|---|---|---|
| 1. 접수 | 고객지원 | 즉시 접수 번호 발급 | 피드백 ID, shop ID, 유형, 접수 시각 |
| 2. 내용 확인·개인정보 제거 | 고객지원 | 1영업일 내 | 내용 있음/빈 제출, 비식별 요약 |
| 3. 기본 일수 계산·지급 | 운영 관리자 | 내용 확인 후 1영업일 내 | 최소 3일, 60일 상한, 지급 원장 ID·지급일 |
| 4. 접수·지급 상태 답변 | 고객지원 | 지급 후 1영업일 내 | 지급 일수 또는 상한 도달, 다음 안내 |
| 5. 중복 묶기·재현·영향 확인 | 제품 QA | 접수 2영업일 내 1차 분류 | 분석용 중복 묶음 ID, 재현 여부, 영향 등급 |
| 6. 제품 후속 | 제품 담당 | 우선순위 결정 후 상태 갱신 | 작업 ID, 반영 예정/완료 상태 |

기본 3일은 `내용 있는 실제 의견`인지와 첫 결제 전 총 60일 상한만 확인한다. 새로움, 심각도, QA 재현 성공, 제품 반영 여부, 중복 여부는 기본 지급 조건이 아니다. 같은 내용이 다른 매장이나 기존 접수와 겹쳐도 각 제출 매장의 의견 한 건으로 최소 3일을 지급한다. 60일 상한에 도달한 뒤에는 추가 일수를 주지 않지만 의견 접수·답변·제품 검토는 계속한다. 빈 제출과 의견 내용 없이 발생한 시스템 오류만 의견 한 건으로 만들지 않는다.

저장하지 않는 정보: 개인 전화번호, 고객 이름·연락처·예약정보·반려동물 정보, PASS 세부정보, 비밀번호·인증번호, DM 대화 전문. 화면 캡처가 필요하면 고객정보를 가리고 필요한 부분만 별도 동의를 받아 처리한다.

## 1등 추가 혜택 비교

1등 경쟁의 공통 자격은 `확정 테스트 매장 + 7일 활성 + 내용 있는 의견 1건 이상 + 운영 원칙 위반 없음`이다. 기본 3일 지급 자격과는 별개이며, 테스트 기간 종료 후 1등 점수 집계가 끝난 시점에 추가 혜택을 지급한다. 대표 승인 전에는 어떤 안도 외부에 약속하거나 UI에 노출하지 않는다.

| 안 | 혜택 | 정확한 표시가치·예산 | 장점 | 주의점 |
|---|---|---|---|---|
| A. 추천 | 서비스 90일 추가 | 1곳 87,000원, VAT 포함 월 29,000원 × 3개월 | 현금 전달·배송 없이 제품 사용과 직접 연결 | 실제 알림톡·인프라 변동비는 별도 측정 필요, 서비스 할인 회계·세무 확인 필요 |
| B | 네이버페이 등 디지털 상품권 | 1곳 최대 100,000원 구매비 | 이해하기 쉽고 체감이 큼 | 구매비·수령 정보가 필요하고 경품·세무·개인정보 검토 필요 |
| C | 서비스 180일 추가 | 1곳 174,000원, VAT 포함 월 29,000원 × 6개월 | 장기 사용과 후속 검증에 유리 | 보상 규모가 크고 매출 인식·변동비 부담이 A보다 큼 |

**추천: A안, 서비스 90일 추가.** 1등 한 곳 기준 표시가치 87,000원이다. 직접 상품권 구매비는 없지만 서비스 제공 중 발생하는 실제 원가는 0원으로 단정하지 않는다.

### 1등 점수와 부정 참여 방지 — 기본 3일과 무관

- 아래 기준은 1등 추가 혜택 순위에만 사용한다. 기본 최소 3일 지급에는 적용하지 않는다.
- 서로 다른 원인으로 QA가 확인한 문제만 1등 점수에 포함한다.
- 영향 등급 점수: 서비스 핵심 진행 불가 8점, 주요 기능 진행 불가 5점, 불편하지만 우회 가능 3점, 문구·가벼운 개선 1점
- 개인정보 없이 재현 순서와 기대 결과를 명확히 남겨 QA 시간을 줄인 경우 2점 추가
- 실제 제품 개선으로 채택된 제안은 3점 추가
- 같은 원인의 중복 제보와 동일 문구 반복은 1등 점수에서만 한 건으로 묶는다. 제출 매장의 기본 3일은 그대로 지급한다.
- 매장당 주 5건, 전체 기간 20건까지만 1등 점수에 반영한다. 그 밖의 내용 있는 의견도 기본 3일 지급과 제품 검토는 그대로 진행한다.
- 제품 QA가 중복·영향 등급을 판정하고 운영 관리자가 점수를 잠근다. 마케팅 담당자는 점수를 임의 변경하지 않는다.
- 허위 재현, 타 매장 내용 복사, 개인정보 포함, 의도적 장애 유발은 1등 점수에서 제외한다. 내용 있는 실제 의견에 대한 기본 3일 정책을 제품 QA가 임의로 보상 제외하는 기준으로 사용하지 않는다.

동점은 `핵심 진행 불가 문제 수 → 실제 반영된 개선 수 → 재현 도움 점수` 순으로 비교한다. 그래도 같으면 공동 1등으로 보고 같은 혜택을 각각 지급한다. A안의 공동 1등 비용은 `87,000원 × 공동 수상 매장 수`이며, 20곳 전원이 완전히 동점인 최댓값은 표시가치 1,740,000원이다. 이 동점 예산 상한도 대표가 보상 공개 전에 승인해야 한다.

1등 여부, 새로움, 심각도, 중복, 재현 결과와 관계없이 내용 있는 실제 의견에는 60일 상한 안에서 최소 3일을 지급하고, 전용 화면에서 처리 상태와 반영 결과를 알려준다. 모든 정상 완료 매장에는 고객에게 노출되지 않는 `초기 테스트 멤버` 감사 표시를 유지해 참여가 1등 경쟁에만 매이지 않게 한다.

## 역할과 처리 시간

| 역할 | 맡는 일 | 기준 시간 |
|---|---|---|
| 마케팅 운영 | 승인된 후보 확인, 1회 발송, 응답·단계 숫자 집계 | 발송 증거 15분 내, 인바운드 답변 1영업일 내 |
| 고객지원 | 가입·설정 순서 안내, 내용 있는 실제 의견 확인, 개인정보 제거, 상태 답변 | 문의·내용 확인 1영업일, 지급 후 답변 1영업일 |
| 제품 QA | 기본 3일과 별도로 분석용 중복 묶음, 재현, 영향 등급·1등 점수 근거 | 접수 후 2영업일 내 1차 분류 |
| 제품 담당 | 확인된 문제의 수정 우선순위와 반영 상태 관리 | 판정 후 2영업일 내 상태 지정 |
| 운영 관리자 | 멤버 상태 관리, 60일 상한 안의 기본 3일 지급, 1등 점수 잠금 | 내용 확인·결정 후 1영업일 내 |
| 분석 담당 | 접촉→가입→확정 테스트→7일 활성 전환 집계 | 매 영업일 종료 후 1회 |

## 후속 제품 작업 분리

아래는 각각 별도 담당이 맡는다. 한 작업 안에서 같은 파일을 두 사람이 동시에 수정하지 않는다.

| 작업 | 담당 범위 | 완료 조건 |
|---|---|---|
| 마케팅 운영 | 추가 후보 기준, 승인 수량 안의 발송·응답·집계 | 공식 채널·중복0·1회 원칙 증거 |
| PC 오너 UI | 테스트 배지·배너·진행률·피드백 CTA·상태 목록 | 일반 사용자 무변경, 고객 화면 노출0, 실제 PC 반응형 QA |
| 모바일 오너 UI | PC와 같은 멤버십·혜택·피드백 상태 표시 | 430px 이하 실제 앱 화면 QA, 고객 화면 노출0 |
| 서버 멤버십·혜택 정본 | shop/user ID 기반 멤버 상태, 첫 결제 30일, 지급 원장·중복 방지 | 일반 가입자 무변경, 권한·중복·취소·재시도 테스트 |
| 분석 | 후보 ID부터 확정 테스트·7일 활성까지 연결 | 개인정보 없는 단계별 고유 매장 집계 |
| 독립 E2E QA | 가입→PASS→3단계→테스트 예약→피드백→보상→첫 결제 30일 검증 | 미해결 치명·주요 문제 0, 실제 환경 증거 |

현재 기존 DB 변경 이력이 정본과 일치하는지 확인하는 **migration-history blocker**가 남아 있다. 이 문제가 해결되고 수용된 기준선이 확정되기 전에는 새 멤버십·혜택 migration을 운영 DB에 적용하지 않는다. 서버 정본 담당은 먼저 기존 이력을 정합화하고, 이후 한 명만 새 cohort·benefit 변경을 작성한다.

## 대표의 다음 결정

지금 당장 외부 연락을 승인할 단계는 아니다. 다음 세 가지가 준비되면 대표에게 한 번에 요청한다.

1. 첫 유료 결제 후 30일 추가의 실제 지급과 독립 E2E PASS
2. 첫 10곳 결과를 바탕으로 계산한 추가 접촉 필요 수와 승인 요청
3. 1등 혜택 A/B/C 중 선택, 동점 공동 지급 예산 상한, 회계·세무 확인 결과

그전까지 외부 연락, 보상 약속, 제품·DB 적용, 광고·게시를 하지 않는다.
