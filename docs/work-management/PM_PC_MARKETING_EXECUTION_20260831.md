### 핵심 ICP

1. **1인 미용실:** 미용 중 전화·카카오 응답 때문에 작업이 끊기고 예약을 수기로 옮기는 대표.
2. **2~4인 미용실:** 직원별 근무시간·서비스 시간·예약 겹침을 한곳에서 정리해야 하는 대표.
3. **도구 분산 매장:** 네이버·카카오·전화로 예약이 나뉘어 고객 요청과 일정 확인이 반복되는 단일 매장.

객실·체크인/아웃·출결·유치원 수업 운영이 핵심인 호텔·유치원은 현재 기능으로 약속하지 않는다.

## 2. UTM·퍼널 이벤트 명세 (구현팀 배정 필요)

### UTM 규칙

| 필드 | 필수값/형식 | 예시 |
|---|---|---|
| `utm_source` | 유입 원천 소문자 | `naver_blog`, `partner`, `retargeting` |
| `utm_medium` | 매체 유형 | `organic`, `referral`, `paid_social` |
| `utm_campaign` | `yyyy-mm_topic_icp` | `2026-09_no-call_solo` |
| `utm_content` | 소재·CTA 구분 | `pain-hero_v1` |
| `utm_term` | 검색어 또는 오디언스 (선택) | `애견미용_예약관리` |

원문 UTM은 첫 방문에 저장하고, 가입·PASS·초기설정·결제 이벤트에 동일 `acquisition_id`로 연결한다. 개인정보나 전화번호를 UTM에 넣지 않는다.

### 필수 이벤트

| 이벤트 | 발생 기준 | 필수 속성 | 성공 지표 |
|---|---|---|---|
| `landing_view` | 랜딩 첫 표시 | `acquisition_id`, UTM, referrer | 유입 |
| `landing_cta_click` | 가입/실제화면 CTA 클릭 | `cta_id` | CTA율 |
| `signup_started` | 약관 다음 단계 진입 | UTM, `signup_flow_version` | 가입 시작 |
| `identity_verified` | PASS 성공 응답 | `signup_flow_version` | PASS 완료 |
| `setup_step_completed` | hours/staff/pricing 각각 저장 | `step_key` | 단계별 완료 |
| `setup_3_completed` | 위 3개 모두 완료 | `elapsed_minutes` | 초기설정 완료 |
| `test_booking_created` | 본인 매장 예약 페이지에서 테스트 예약 1건 | `booking_source=test` | 첫 예약 준비 |
| `first_real_booking_created` | 실제 예약 1건 | `booking_source=customer` | 첫 실예약 |
| `activated_day_7` | 가입 후 7일 이내 운영 기준 충족 | `activation_rule_version` | 7일 활성 |
| `paid_conversion` | 유료 결제 성공 | `plan_code`, `days_from_signup` | 유료전환 |

`activated_day_7`의 첫 정의는 “가입 후 7일 안에 테스트 또는 실제 예약 1건 + 서로 다른 2일에 오너 운영 화면 사용”으로 제안한다. 구현 전 제품·데이터 담당이 가능한 이벤트로 확정한다.

### 구현 요청 범위

현재 마케팅 KPI에는 랜딩 방문, CTA 클릭, 귀속이 `not_instrumented`로 정의되어 있다. 구현팀은 위 이벤트를 익명 `acquisition_id`로 기록하고, 운영 KPI와 채널별 집계를 가능하게 해야 한다. 제품 코드 수정은 이 업무 범위 밖이다.
