# 업무 기록 틀 — 주담당이 작성

대표에게 이 양식을 채우도록 요구하지 않습니다. 한 업무/한 파일 집합의 제품 작성자는 한 명이며, 같은 업무 구현자는 독립 검수를 하지 않습니다.

- 상위 업무 ID(`parent_work_id`) / 짧은 업무명:
- 대표 요청 요약:
- 대표 우선순위 변경: 없음 | 있음(근거):
- 상태: 지시사항 | 작업중 | 조치필요 | 검수필요 | 완료
- UI 영향: Y/N 및 이유
- 대상 프로젝트 / 실제 작업 경로:
- 범위 / 하지 않을 일:
- 완료 조건:
- 상위 acceptance gate / 독립 QA 필요 여부:
- 단계 표: `step_id | lane | depends_on | 상태(pending/active/blocked/stalled/qa/rework/completed) | 단계 완료 조건 | 담당 | last_output_at | resume_attempted`
- 현재 `next-ready` / 선택 근거:
- 현재 기준선: 브랜치·커밋·보존할 미커밋 변경 / 확인 시각
- 현재 지침·역할 파일이 이 작업본에 실제 포함됐는지:
- 기존 작성자 중지·변경 소유권 확인 근거:
- 주담당 / 조사 / UI 설계 / 유일 구현자 / 독립 기능·화면 검수자:
- 구현자 쓰기 허용 파일 / QA 산출물·임시 경로:
- 승인 경계와 승인 기록: 필요 없음 또는 승인자·범위·근거
- 실제 실행 근거 / 마지막 확인 시각:
- 검증 결과: 조건별 PASS/FAIL/검증불가, 미해결 P0/P1 수·정확한 수정 항목과 증거 경로
- 시작한 서버·브라우저: PID·부모 PID·실행 인수·프로필 / 종료 확인
- blocker: 원인 / 재개 조건 / 영향 단계 / 해제 후 next-ready / `owner_approval_required: Y/N` / 필요한 대표 결정:

## 짧은 인계

목적, 확정 결정, 변경 파일, 검증된 결과, 막힘, 다음 단계만 적습니다. 새 담당은 이 인계와 필수 파일을 읽고 실제 작업공간을 다시 확인합니다. 원문 대화·전체 로그·원시 사용자 프롬프트·비밀·개인정보는 저장하지 않습니다.

## 완료 판단

미해결 P0/P1이 0건이고 전체 완료 조건과 필요한 독립 검수가 모두 PASS이며 실행 근거·작업 소유 프로세스 종료 확인이 있는 경우에만 완료로 바꿉니다. 검증불가는 통과가 아닙니다. 검수 실패는 같은 업무 ID의 구현자에게 최소 수정 항목으로 반환합니다. 외부 승인 대기를 자동 재시도하지 않습니다.

개별 task의 `completed`는 단계 산출물 제출일 뿐 상위 완료가 아닙니다. QA 실패는 같은 `parent_work_id`와 같은 `step_id`를 `rework`로 되돌린 뒤 재검수합니다. `interrupted`/`failed`/10분 무출력은 `stalled`이며, 같은 단계 재개 신호 1회 뒤 다시 정체되면 쓰기 중지·소유권 반환을 확인하고 compact handoff로 담당만 교체합니다.
