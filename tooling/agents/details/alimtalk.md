# 알림톡 공통 발송 계약

이 파일은 PC와 모바일의 예약 안내, 픽업 준비 알림, 발송 대상, 템플릿·문구, 중복 방지, 실패 처리, 원장과 보안을 다룰 때만 읽는다. 두 플랫폼은 같은 계약을 사용하며 서로 다른 알림톡 정책을 만들지 않는다. 실제 발송과 외부 변경은 공통 승인 경계를 따른다.

## 예약 안내 정책

- 고객 예약 알림은 아래의 예약 방문 안내를 제외하면 오너 수동 동작이 기본이다.
- 예약 방문 안내 알림톡은 승인된 자동 흐름이며 예약당 가장 적절한 시점에 최대 한 번만 보낸다.
- 미리 잡힌 예약은 전날 `내일 예약 안내`, 당일에 충분한 여유를 두고 잡힌 예약은 `오늘 예약 안내`, 시작 직전에 잡힌 예약은 유효할 때 `직전 예약 안내` 하나만 보낸다.
- 한 종류가 자동 발송되면 같은 예약에 다른 자동 예약 안내를 추가 발송하지 않는다. 여러 시간 창이 있다는 이유로 중복 예약 안내를 만들지 않는다.
- 수동 버튼이 있으면 재발송·테스트·수동 override 같은 보조 기능이며 기본 흐름으로 설명하지 않는다.
- 자동 안내도 매장 알림 설정, 보호자/매장 수신 거부, 중복 방지, 승인된 Ssodaa 템플릿 mapping과 매장 크레딧 잔액을 지킨다.
- 대표의 명시적 승인 없이 다른 알림 종류나 새 background cron을 추가하지 않는다.
- 발송 대상은 정본 예약·보호자 데이터에서 확인된 해당 고객이어야 한다. 화면 입력이나 오래된 복사값으로 수신자를 바꾸지 않는다.

## 크레딧과 원장

- Ssodaa 잔액은 플랫폼 pool이고, PetManager는 매장별 내부 크레딧을 관리한다. 매장 잔액이 없으면 발송을 막는다.
- 성공한 provider 결과만 발송 성공으로 기록하고 매장 크레딧 1건을 원장과 함께 차감한다. provider 실패는 성공으로 표시하지 않고 예약한 크레딧을 환불한다.
- 요금제 포함 크레딧은 유료 기간마다 초기화하며 미사용분은 이월하지 않는다. 별도 유료 구매 크레딧은 대표가 환불·조정·정책 변경을 요청하지 않는 한 만료·초기화하지 않는다.

## 템플릿·문구 계약

- Ssodaa 템플릿 생성·수정·심사 제출은 대표가 PetManager 등록을 명시적으로 요청하지 않는 한 Ssodaa에서 직접 수행한다.
- PC와 모바일은 같은 승인 템플릿 코드, 본문, 버튼과 허용된 치환 변수 계약을 사용한다. 플랫폼별 임의 문구나 별도 템플릿 의미를 만들지 않는다.
- PetManager 화면은 승인된 템플릿 코드 연결과 본문·버튼 비교를 지원할 수 있지만, 명시적 승인 없이 앱 안 템플릿 등록 흐름을 만들지 않는다.
- `grooming_completed` 같은 alias를 실제 Ssodaa 템플릿 코드로 사용하지 않는다. 승인 code mapping이 없으면 발송을 차단/queue하고 누락을 보고한다.
- 실제 발송 문구가 승인 본문·버튼·치환 규칙과 다르면 환경 성공 여부와 무관하게 템플릿 불일치로 처리하고 발송을 진행하지 않는다.

## 중복·실패·기록·보안

- 예약 안내 종류 중 하나가 발송되면 같은 예약의 다른 자동 안내를 막는 durable 중복 방지 기록을 사용한다. 불확실한 timeout이나 재시도도 같은 예약·발송 목적의 idempotency 경계를 통과해야 한다.
- provider 실패와 timeout은 안전한 실패 상태로 기록하고 자동으로 성공 처리하거나 다른 템플릿으로 fallback하지 않는다. 재시도는 중복 방지와 크레딧 환불/재예약 상태를 먼저 확인한다.
- 발송 기록에는 매장·예약·발송 목적·승인 템플릿 식별자·결과·안전한 오류 코드처럼 운영에 필요한 최소 정보만 남긴다.
- 전체 전화번호, 인증키·토큰·secret, 승인되지 않은 전체 메시지 본문, provider 원시 오류 body를 채팅·클라이언트·일반 로그에 노출하지 않는다.
- 서버 실행 환경의 설정·상태 확인·재배포·장애 진단은 이 공통 계약이 아니라 별도의 백엔드 릴레이 운영 절차로 관리한다.
