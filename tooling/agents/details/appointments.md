# 예약·일정·상태 상세 규칙

이 파일은 예약 생성·변경, 캘린더, 예약 관리, 일정판, 스태프 배정, 미용 상태 동기화를 다룰 때만 읽는다.

## 단일 예약 원본과 갱신

- 캘린더, 예약 관리, 일정판은 같은 정본 `appointments` 행의 projection이다. 화면별 예약 복사본, fallback 행, production 독립 demo state를 만들지 않는다.
- 보이는 예약 범위는 최초 진입과 날짜/범위 변경 시 서버에서 갱신하고, 화면이 보이는 동안 주기적으로 그리고 focus/visibility 복원 시 다시 갱신한다.
- 범위 병합은 날짜뿐 아니라 durable row `id`로 예약과 미용 기록을 조정한다. 한 행이 범위 밖으로 이동했을 때 같은 ID의 중복이나 오래된 사본이 남으면 안 된다.
- 모바일 상태 변경은 같은 appointment API를 통해 PC에 반영하고, PC 보이는 일정은 외부 변경을 주기적으로 다시 읽는다.

## 겹침과 현재 작업

- 같은 매장·스태프의 활성 예약 겹침 방지는 PostgreSQL 트랜잭션 수준에서 동시성 안전해야 한다. 클라이언트 검사나 non-locking trigger만으로 대체하지 않는다.
- `prevent_overlapping_staff_appointments()`의 per-shop/per-staff 직렬화를 동등한 concurrent-write DB 테스트와 대표 승인 없이 약화하거나 제거하지 않는다.
- 겹침 DB 오류는 실행 가능한 한국어 안내로 변환하고 raw PostgreSQL 오류를 오너나 고객에게 노출하지 않는다.
- 일정판 현재 작업 기준은 현재 시각이 예약 시간 범위 안에 있는 활성 예약 중 시작 시각이 가장 빠른 항목이다. 활성 상태는 `진행 중`, `픽업 준비`이며 시간이 지난 항목은 기준이 아니다.

## 스태프·일정 표시

- 일정 스태프 열과 필터는 저장된 스태프만 사용한다. 해당 화면의 명시적 요청 없이 `미배정` 같은 합성 열·옵션을 추가하지 않는다.
- 스태프가 정확히 한 명이면 담당 필터를 그 스태프로 고정하고 `전체 스태프`를 표시하지 않는다.
- 밀도 높은 일정은 수직 시간 위치와 비겹침을 먼저 보존한다. 예약을 시각적으로 겹쳐 쌓지 말고 가능한 스태프/시간 창에 배정한다.
