# PC 관리자·오너 UI 상세 규칙

이 파일은 `D:\petmanager`의 관리자·오너 화면, 일정·캘린더 카드, 상태 표시, 작업실 화면을 변경할 때만 읽는다.

## 실제 화면 확인

- UI 변경은 실제 화면/소스 확인 → 간단한 방향 확정 → 단일 구현 → 구현 담당의 대표용 실제 화면 확인 → 완료 순서다.
- 다른 명시적 화면 계약이 없다면 구현 담당은 1440, 1024, 390 너비에서 상호작용, 문서 overflow, console/page 오류, 반응형 배치와 접근 가능한 조작 대상을 확인한다.
- 조작 대상은 문서화된 고정 geometry 예외가 없으면 최소 44px를 유지한다.
- PetManager UI playbook을 사용할 수 있으면 새 UI 작업 경계에서 한 번 읽고 적용한다.

## 일정·스태프 화면

- 일정판은 흰색/중립 카드, 옅은 grid, 간결한 스태프 header를 사용하고 포화된 전체 카드 배경을 사용하지 않는다.
- 날짜 이동은 왼쪽 chevron, 가운데 평문 날짜, 오른쪽 chevron 순서를 사용한다.
- 스태프 주간 일정 셀은 별도 승인 없이 `h-9`의 간결한 높이를 유지한다.
- 주간 일정 편집 modal의 `기본 근무 설정`은 기본으로 접고, 오너가 header를 열었을 때만 요일/시간 조작을 표시한다.
- 열은 `스태프명`, `월`, `화`, `수`, `목`, `금`, `토`, `일` 순서다. 스태프 셀은 이름을 굵게, 역할/서비스를 작은 muted text로 표시한다.

## 상태 표시 계약

- 재사용 상태 모양은 작은 채움 점인 `상태 점`과 카드·일정 항목의 `좌측 엣지 인디케이터` 두 가지다.
- 카드 정본 표식은 `PM_STATUS_LEFT_EDGE`이며 parent `position: relative`, `overflow: hidden`, 중립 1px 전체 border, 3px 왼쪽 border, `var(--pm-wrap-indicator-color)`, 8px radius, 흰 배경을 사용한다. pseudo-element나 child rail을 추가하지 않는다.
- 대표 승인 없이 이 계약을 바꾸지 않는다. 내부 세로선, 분리 rail, bracket, pill chip, 두꺼운 border, 포화된 전체 배경, gradient, 무거운 shadow, `border-2`, 포화 focus ring, 일정 카드의 dot-only 상태는 금지한다.
- 고정 색은 성공/확정 `#1f9d55`, 진행 `#2563eb`, 픽업 준비 `#7c3aed`, 근무 `#607080`, 대기/예정/변경 `#b98121`, 휴무/취소/거절/실패 `#a04455`, 완료 `#64748b`, 미확인/비활성 `#b9c3cf`다.
- PC에서는 `src/components/owner-web/status-indicators.ts`를 재사용하고 일정·캘린더·스태프·고객 화면에 다른 색을 hard-code하지 않는다.

## 관리자 작업실 표시

- 대표 요청은 쉬운 한국어 한 문장으로 표시한다.
- 일반 UI 작업은 `UI 설계 -> 구현·직접 확인 -> 완료`의 최소 흐름과 현재 단계를 보여준다. 위험도 규칙이나 대표 요청이 있을 때만 `독립 QA`를 추가한다.
- 이유, 대기 주체, 다음 행동, 대표 결정 필요 여부, 확인 시각과 근거 출처를 평문으로 보여준다.
- raw 대화, 개인정보, 내부 추론, 명령, 원시 도구 출력을 노출하지 않는다. 대표 결정이 실제로 필요할 때만 CTA 하나를 표시한다.
